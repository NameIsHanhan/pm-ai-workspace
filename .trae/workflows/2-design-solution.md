# 🏗️ Phase 2：方案架构（Design Solution）

> 第二阶段工作流：基于需求分析，设计完整的产品解决方案。

---

## 🎯 目标

将需求分析转化为具体的产品方案，包括功能架构、交互设计、数据模型等。

## 📥 输入

- Phase 1 的需求分析文档
- 影响范围评估报告
- 用户故事清单
- 项目上下文（`context/` 目录）

## 📤 输出

- 功能架构设计（存放至 `drafts/`）
- 交互流程图（存放至 `assets/diagrams/`）
- 数据字段清单初稿（存放至 `drafts/`）
- 风险探测报告（存放至 `analysis/scope-analysis/`）

## 🔧 调用的 Skills

| Skill | 用途 | 执行顺序 |
|-------|------|----------|
| <a>Data-Modeler</a> | DDD 思维设计数据模型，企业级数据库规范 | 先执行 |
| <a>Edge-Case-Detector</a> | 5 维扫描识别风险和异常场景 | 后执行 |

> **使用方式**：在 AI IDE 中引用 `@data-modeler` 和 `@edge-case-detector`

---

## 🔄 执行步骤

### Step 1：功能架构设计

**提示词模板**：

```
基于以下需求分析，请帮我设计功能架构。

【需求分析】
{引用 Phase 1 输出}

请输出：
1. 功能模块划分（树形结构）
2. 各模块核心功能点
3. 模块间的依赖关系
4. MVP 范围建议（分期策略）
```

### Step 2：交互流程设计

**提示词模板**：

```
请为以下功能设计详细的交互流程。

【功能模块】
{描述需要设计的功能模块}

【用户故事】
{引用相关用户故事}

请输出：
1. 主流程（用 Mermaid 流程图表示）
2. 页面流转关系
3. 关键交互节点说明
4. 异常处理流程
```

### Step 3：数据模型设计（使用 Data-Modeler）

**提示词模板**：

```
请用资深数据架构师模式，为以下功能设计数据模型。

【功能架构】
{引用 Step 1 输出}

请严格遵循企业级数据库规范输出：
1. 核心数据实体及其关系（ER 图，用 Mermaid 表示）
2. 完整字段清单（表格形式）：
   - 字段名（中文）、字段名（英文）、类型、必填、默认值、说明/校验规则、枚举值
   - 主键使用雪花 ID（BIGINT），禁止自增 ID
   - 所有表必须包含审计字段：created_by、created_at、updated_by、updated_at、is_deleted、deleted_at、version
   - 金额使用 DECIMAL(20,6)，状态使用 TINYINT，时间使用 DATETIME
3. 状态流转图（如有状态字段）
4. 索引建议（唯一索引、普通索引）
```

### Step 4：页面原型草案

**提示词模板**：

```
请基于以下交互设计，生成页面原型的 HTML 代码。

【交互流程】
{引用 Step 2 输出}

【字段清单】
{引用 Step 3 输出}

要求：
1. 使用 HTML + CSS（内联样式）
2. 采用 Ant Design 风格
3. 包含示例数据
4. 标注交互说明（作为 HTML 注释）
5. 响应式布局
```

### Step 5：异常场景扫描（使用 Edge-Case-Detector）

**提示词模板**：

```
请用异常探测专家模式，对以下方案进行 5 维风险扫描。

【功能架构】
{引用 Step 1 输出}

【数据模型】
{引用 Step 3 输出}

请从以下 5 个维度识别风险：
1. 交互异常（表单重复提交、页面刷新、网络超时等）
2. 并发冲突（超卖、重复支付、幂等性等）
3. 数据一致性（主从延迟、分布式事务、缓存一致性等）
4. 权限安全（越权访问、敏感数据泄露、CSRF 等）
5. 时间与环境（跨日边界、时区、定时任务等）

输出格式：风险探测报告，包含优先级（P0/P1/P2）和解决方案
```

## ✅ 完成检查清单

- [ ] 功能架构清晰完整
- [ ] 交互流程覆盖所有场景
- [ ] 数据模型合理（符合企业级规范）
- [ ] 字段清单准确（含审计字段、索引建议）
- [ ] 页面原型可供评审
- [ ] 技术可行性已初步验证
- [ ] 风险探测报告已生成

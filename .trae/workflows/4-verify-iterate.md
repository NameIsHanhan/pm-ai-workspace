# ✅ Phase 4：验证迭代（Verify & Iterate）

> 第四阶段工作流：对产出物进行多维度验证，发现问题后回溯修正。

---

## 🎯 目标

通过系统化的验证，确保交付物质量达标，建立问题回溯和持续改进机制。

## 📥 输入

- Phase 3 的正式 PRD 文档
- 字段清单
- 风险探测报告
- 前端 Demo（如有）

## 📤 输出

- AC 验收标准清单
- 自检报告
- 修正后的终版文档

---

## 🔄 执行步骤

### Step 1：4 维自检清单

对 PRD 文档进行 4 维度交叉验证：

#### 📐 维度一：逻辑自检

- [ ] 业务规则是否有矛盾
- [ ] 状态流转是否闭环（每个状态都有进入和退出路径）
- [ ] 条件分支是否完整（if-else 是否都覆盖）
- [ ] 数字计算逻辑是否正确（价格、折扣、税费）
- [ ] 时间线是否合理（流程前后依赖是否正确）

#### 📊 维度二：数据自检

- [ ] 字段清单是否完整（不缺字段）
- [ ] 字段类型是否准确（金额用 Decimal、状态用枚举）
- [ ] 枚举值是否完整（不遗漏选项）
- [ ] 必填/选填标注是否正确
- [ ] 字段长度是否合理
- [ ] 数据来源是否明确

#### 🔐 维度三：权限自检

- [ ] 各角色的权限边界是否清晰
- [ ] 数据隔离是否到位（A 看不到 B 的数据）
- [ ] 敏感操作是否有二次确认
- [ ] 审计日志是否覆盖关键操作
- [ ] 敏感字段是否有脱敏规则

#### 🖥️ 维度四：前端自检

- [ ] 页面布局是否完整（表单、列表、详情）
- [ ] 交互反馈是否齐全（Loading、成功、失败提示）
- [ ] 空状态处理（无数据时的展示）
- [ ] 分页/滚动加载是否考虑
- [ ] 移动端适配（如需要）
- [ ] TypeScript 类型定义是否准确

### Step 2：AC 验收标准生成

**提示词模板**：

```
请基于以下 PRD 文档，生成完整的验收标准清单。

【PRD 文档】
{引用 PRD 内容}

要求：
1. 使用 Given-When-Then 格式
2. 覆盖正常场景和异常场景
3. 包含边界值测试
4. 标注优先级（P0/P1/P2）
```

### Step 3：问题回溯机制

发现问题后，根据问题类型回溯到对应的 Phase 修正：

| 问题类型 | 回溯目标 | 诊断问题 | 修正动作 |
|----------|----------|----------|----------|
| 需求理解偏差 | Phase 1 | 用户的真实痛点是否被准确识别？是否存在 X-Y Problem？ | 重新执行 Requirement-Clarifier |
| 数据模型问题 | Phase 2 | 字段类型/关系是否有误？是否遗漏审计字段或索引？ | 重新执行 Data-Modeler |
| 遗漏异常场景 | Phase 2 | 哪个维度（交互/并发/一致性/权限/时间）的风险未覆盖？ | 重新执行 Edge-Case-Detector |
| 文档描述不清 | Phase 3 | 哪个章节存在歧义或缺失信息？ | 修正 PRD 具体章节 |
| 字段定义错误 | Phase 3 | 具体哪些字段的类型、必填、枚举值有误？ | 修正字段清单 |

### Step 4：经验沉淀

每次验证迭代后，更新 `AGENT.md`：

1. 在"经验教训"章节记录发现的问题和改进方案
2. 在"最佳实践"章节补充新的最佳实践
3. 在"项目演进日志"中记录里程碑

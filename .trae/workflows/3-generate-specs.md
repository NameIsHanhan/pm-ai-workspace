# 📄 Phase 3：规格生成（Generate Specs）

> 第三阶段工作流：将方案设计转化为正式的、可交付的产品规格文档。

---

## 🎯 目标

生成完整的、可交付给研发团队的产品规格文档，包括正式 PRD、字段清单、接口需求等。

## 📥 输入

- Phase 2 的方案设计文档
- 功能架构图
- 交互流程图
- 数据字段清单初稿

## 📤 输出

- 正式 PRD 文档（存放至 `prds/`）
- 完整字段清单（包含在 PRD 中或独立文档）
- 接口需求文档（如需要）
- 交付文档（存放至 `outputs/`）

---

## 🔄 执行步骤

### Step 1：PRD 文档生成

**提示词模板**：

```
请基于以下方案设计，生成完整的 PRD 文档。

【功能架构】
{引用 Phase 2 Step 1 输出}

【交互流程】
{引用 Phase 2 Step 2 输出}

【数据模型】
{引用 Phase 2 Step 3 输出}

请按以下结构生成 PRD：

1. 文档信息（标题、版本、日期、作者、审核人）
2. 修订记录
3. 需求背景与目标
4. 名词解释
5. 功能范围（In Scope / Out of Scope）
6. 用户故事
7. 功能需求（按模块组织）
   - 功能描述
   - 业务规则
   - 交互说明
   - 字段清单
   - 异常处理
8. 非功能需求
9. 数据需求
10. 上线计划
11. 风险与依赖
12. 附录
```

### Step 2：字段清单完善

**提示词模板**：

```
请完善以下字段清单，确保符合交付标准。

【初始字段清单】
{引用 Phase 2 的字段清单}

请补充完善以下内容：
1. 校验规则（正则表达式或文字描述）
2. 前端展示规则（显示/隐藏条件、格式化规则）
3. 权限控制（谁可以查看/编辑）
4. 数据来源（手工输入/系统生成/接口获取）
5. 历史兼容性说明

输出格式要求：表格形式，包含所有字段的完整信息。
```

### Step 3：PRD 质量审查

**提示词模板**：

```
请对以下 PRD 文档进行质量审查。

【PRD 文档】
{引用 Step 1 生成的 PRD}

请从以下维度进行审查：
1. 完整性：是否有遗漏的功能点或场景
2. 一致性：描述是否前后一致
3. 可测试性：需求是否可以被测试验证
4. 无歧义性：是否存在模糊或多义的描述
5. 可行性：技术实现是否合理
6. 用户体验：交互设计是否合理

请输出：
- 问题清单（按严重程度排序）
- 修改建议
- 优化建议
```

### Step 4：交付物打包

完成审查和修改后：

1. 将最终 PRD 从 `drafts/` 移至 `prds/`
2. 如需对外交付，复制一份到 `outputs/client-prds/`
3. 更新 `AGENT.md` 的项目演进日志
4. 将过程中的经验教训记录到 `AGENT.md`

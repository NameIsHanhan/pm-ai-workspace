# 📋 Phase 1：需求洞察（Analyze Requirement）

> 第一阶段工作流：深入理解和分析需求，为后续方案设计奠定基础。

---

## 🎯 目标

通过系统化的需求分析，确保对业务需求有全面、深入的理解，输出清晰的需求分析文档。

## 📥 输入

- 原始需求描述（口头、邮件、文档等）
- 业务背景信息（参考 `context/` 目录）
- 相关参考资料（参考 `docs/` 目录）

## 📤 输出

- 需求分析文档（存放至 `drafts/`）
- 影响范围评估（存放至 `analysis/scope-analysis/`）

---

## 🔧 调用的 Skills

| Skill | 用途 |
|-------|------|
| [Requirement-Clarifier](./../skills/requirement-clarifier.md) | 识别 X-Y Problem，使用 JTBD 进行结构化追问 |

> **使用方式**：在 AI IDE 中引用 `@requirement-clarifier` 或 在对话中说"请用需求挖掘专家模式分析"

## 🔄 执行步骤

### Step 1：需求收集与澄清（Requirement-Clarifier）

**提示词模板**：

```
请用需求挖掘专家（Requirement-Clarifier）的方式分析以下需求。

【原始需求】
{粘贴原始需求描述}

【已知背景】
{补充已知的背景信息}

请帮我：
1. 识别是否存在 X-Y Problem（用户给的是方案还是问题？）
2. 使用 JTBD 框架追问：当[情境]时，用户想要[目标]，这样能[价值]
3. 提炼核心需求点，区分"真实问题"和"解决方案"
4. 列出需要进一步确认的问题清单
5. 初步判断需求的优先级和复杂度
6. 输出 RDD 需求定义卡片
```

### Step 2：用户故事梳理

**提示词模板**：

```
基于以下需求分析，请帮我梳理完整的用户故事。

【需求分析】
{引用 Step 1 的输出}

请按以下格式输出：
- 角色（As a...）
- 行为（I want to...）
- 目的（So that...）
- 验收标准（Acceptance Criteria）

同时请识别：
1. 主流程（Happy Path）
2. 分支流程
3. 异常场景
```

### Step 3：影响范围评估

**提示词模板**：

```
请评估以下需求的影响范围：

【需求概述】
{简述需求}

【用户故事】
{引用 Step 2 的输出}

请从以下维度进行评估：
1. 受影响的模块/页面
2. 数据变更（新增/修改的数据实体和字段）
3. 接口变更
4. 对现有功能的影响
5. 上下游系统影响
6. 用户体验影响
```

### Step 4：竞品参考（可选）

**提示词模板**：

```
针对以下功能需求，请帮我进行竞品分析：

【功能需求】
{简述核心功能}

请分析：
1. 主流产品是如何实现类似功能的
2. 各竞品的优缺点
3. 值得借鉴的设计模式
4. 我们可以差异化的点
```
